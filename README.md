1. GIT 

Базовые локальные команды
git init
Что делает: Создает новый пустой локальный репозиторий Git в текущей папке (создает скрытую директорию .git).
Зачем нужна: Чтобы начать отслеживать изменения в новом или существующем проекте, который ранее не использовал Git. [1 (https://www.tgu-dpo.ru/news/2026/08/09/chto-takoe-git/), 2 (https://git-scm.com/docs/git-init/ru)]

git add
Что делает: Переносит измененные или новые файлы из рабочей директории в индекс (Staging Area / область подготовленных файлов).
Зачем нужна: Служит промежуточным шагом перед сохранением. Позволяет точно выбрать, какие именно изменения войдут в следующий слепок (коммит), а какие пока останутся нетронутыми. [1 (https://www.atlassian.com/ru/git/glossary), 2 (https://git-scm.com/book/ru/v2/%D0%9F%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5-C:-%D0%9A%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%D1%8B-Git-%D0%9E%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D1%8B%D0%B5-%D0%BA%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%D1%8B), 3 (https://www.tgu-dpo.ru/news/2026/08/09/chto-takoe-git/)]

git commit
Что делает: Сохраняет все подготовленные (с помощью git add) файлы в историю проекта, создавая постоянный «снимок» (слепок) состояния кода с уникальным хэшем.
Зачем нужна: Чтобы зафиксировать рабочую точку, к которой можно будет вернуться в любой момент, если что-то пойдет не так. [1 (https://habr.com/ru/companies/netologyru/articles/1012264/), 2 (https://git-scm.com/book/ru/v2/%D0%9F%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5-C:-%D0%9A%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%D1%8B-Git-%D0%9E%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D1%8B%D0%B5-%D0%BA%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%D1%8B), 3 (https://www.tgu-dpo.ru/news/2026/08/09/chto-takoe-git/)]

Взаимодействие с удаленным репозиторием (GitHub, GitLab и др.)
git fetch
Что делает: Скачивает данные, ветки и историю изменений из удаленного репозитория на ваш компьютер, но не объединяет их с вашим текущим кодом.
Зачем нужна: Чтобы безопасно узнать, какие изменения появились у коллег, проверить их и не сломать при этом свою текущую работу. [1 (https://devopsgu.ru/guides/shpargalka-po-git/), 2 (https://www.atlassian.com/ru/git/glossary)]

git push
Что делает: Выгружает ваши локальные сохраненные коммиты в удаленный репозиторий.
Зачем нужна: Чтобы поделиться своим кодом с командой или сохранить резервную копию проекта на сервере. [1 (https://www.nic.ru/help/zachem-nuzhna-komanda-git-push_11631.html)]
git pull

Что делает: Работает как автоматическая цепочка из двух команд: сначала скачивает изменения (git fetch), а затем сразу вливает их в текущую ветку (git merge).
Зачем нужна: Чтобы быстро обновить свой локальный код до самой актуальной версии, которая сейчас находится на сервере. [1 (https://git-scm.com/book/ru/v2/%D0%9F%D1%80%D0%B8%D0%BB%D0%BE%D0%B6%D0%B5%D0%BD%D0%B8%D0%B5-C:-%D0%9A%D0%BE%D0%BC%D0%B0%D0%BD%D0%B4%D1%8B-Git-%D0%A1%D0%BE%D0%B2%D0%BC%D0%B5%D1%81%D1%82%D0%BD%D0%B0%D1%8F-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0-%D0%B8-%D0%BE%D0%B1%D0%BD%D0%BE%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5-%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D0%BE%D0%B2)]

Объединение веток и управление историей
git merge
Что делает: Сливает указанную ветку (например, ветку с новой фичей) в вашу текущую ветку.
Зачем нужна: Интегрирует выполненную работу из одной ветки в другую.
Разница флагов:
--no-ff (No Fast-Forward): Принудительно создает отдельный коммит слияния, даже если ветки можно было объединить по прямой линии. Это полезно, так как в истории наглядно сохраняется вся структура ветвления проекта.
--squash: Берет все коммиты из вливаемой ветки, «схлопывает» их в одно большое изменение и предлагает сделать один аккуратный коммит в целевой ветке. Зачем? Чтобы не засорять общую историю десятками мелких промежуточных коммитов вроде «исправил опечатку» или «тест 2».

git rebase
Что делает: Переносит основание вашей текущей ветки на самый свежий коммит другой ветки (будто вы начали писать свой код только что, поверх самых последних изменений).
Зачем нужна: Позволяет сделать историю проекта идеально линейной и красивой, без создания лишних «технических» коммитов слияния (которые делает обычный git merge). [1 (https://cloud.ru/blog/chto-takoye-git-rebase-i-kak-rabotayet)]

Расширение методологии
git flow
Что делает: Это не базовая команда самого Git, а стороннее расширение (плагин), добавляющее высокоуровневые команды для управления ветками по строгой методологии Git Flow (команды вида git flow feature start, git flow release finish).
Зачем нужна: Помогает автоматизировать рутину в больших командах. Она сама следит за правильным созданием веток для фич, релизов и срочных исправлений (hotfix) и за их последующим слиянием в главные ветки (обычно main/master и develop), избавляя разработчика от необходимости вручную вводить цепочки из git branch, git checkout и git merge.

2. Docker

Для управления контейнерами и проектами.
docker run
Что делает: Берет готовый образ (Image) и запускает на его основе новый изолированный контейнер. Если образа нет на вашем компьютере, Docker автоматически скачает его из интернета (Docker Hub).
Зачем нужна: Чтобы быстро запустить одну конкретную программу или утилиту в изолированной среде (например, запустить базу данных одной командой).

docker exec
Что делает: Выполняет команду внутри уже запущенного контейнера. Чаще всего используется в виде docker exec -it <имя_контейнера> bash (или sh).
Зачем нужна: Чтобы «войти» внутрь работающего контейнера, проверить файлы, логи, запустить консольные команды или провести диагностику без перезапуска приложения.

docker compose
Что делает: Это инструмент (и единая команда) для управления многоконтейнерными приложениями. Она считывает специальный конфигурационный файл docker-compose.yml, где описаны все связанные друг с другом сервисы, сети и хранилища вашего проекта.
Зачем нужна: Чтобы не запускать вручную пять-десять разных контейнеров (например, бэкенд, фронтенд, базу данных и кэш) через длинные команды docker run. Вы описываете всю архитектуру в одном файле, а Docker Compose управляет ими как единым целым.

Подкоманды для Docker Compose
docker compose up (в старых версиях писалось через дефис: docker-compose up)
Что делает: Собирает, создает, запускает и связывает между собой все контейнеры, описанные в файле docker-compose.yml. Флаг -d запускает их в фоновом режиме.
Зачем нужна: Одной командой развернуть и запустить весь проект со всеми его зависимостями «с нуля».

docker compose down
Что делает: Останавливает и полностью удаляет контейнеры, сети и внутренние хранилища, которые были созданы командой up.
Зачем нужна: Чтобы полностью очистить рабочее окружение и остановить проект, освободив оперативную память и порты на компьютере. При этом ваши исходные данные в примонтированных папках (volumes) на жестком диске не удаляются.

Контейнер — это стандартизированный, изолированный «короб» для программы, внутри которого упаковано само приложение и абсолютно все зависимости, необходимые для его работы (код, среда выполнения, библиотеки, системные утилиты и настройки).
Если говорить простыми словами, это готовая к запуску мини-система, которая гарантирует, что программа будет работать одинаково на любом компьютере — будь то ноутбук разработчика, тестовый сервер или облако.
Часто контейнеры путают с виртуальными машинами (как VirtualBox или VMware), но они устроены гораздо эффективнее:
Виртуальная машина тащит с собой целую гостевую операционную систему (например, 5 ГБ Windows или Linux). Она требует много оперативной памяти, процессора и загружается минутами.
Контейнер не содержит внутри себя операционную систему. Он детит (использует совместно) ядро процессора и ОС вашего компьютера. Внутри контейнера находятся только файлы самой программы. Поэтому контейнер весит мегабайты, не тратит лишнюю память и запускается за доли секунды.

3. Linux

Работа с файлами и папками (Навигация и создание)
ls (List)
Что делает: Выводит список файлов и папок в текущей директории. Часто используется с флагами, например ls -la (показать скрытые файлы и подробную информацию: права, размер, дату).
Зачем нужна: Чтобы «осмотреться» вокруг и понять, какие файлы находятся в папке, где вы сейчас стоите.

cd (Change Directory)
Что делает: Переводит вас в указанную папку (например, cd /var/log или cd .. для перехода на один уровень вверх).
Зачем нужна: Для перемещения по файловой системе компьютера.

mkdir (Make Directory)
Что делает: Создает новую пустую папку с указанным именем.
Зачем нужна: Чтобы организовать структуру проекта и подготовить место для новых файлов.

touch
Что делает: Создает новый пустой файл (если его не существовало). Если файл уже есть, команда просто обновляет дату его последнего изменения, не трогая содержимое.
Зачем нужна: Быстрый способ создать текстовый файл, конфигурацию или скрипт (например, touch index.html), чтобы потом наполнить его кодом.

Просмотр и редактирование текста
cat (Concatenate) / nano
Что делают:
cat просто выводит все содержимое текстового файла прямо в консоль.
nano открывает простой и удобный текстовый редактор прямо внутри терминала.
Зачем нужны: cat идеален, когда нужно быстро прочитать лог-файл или конфигурацию, не открывая редактор. nano нужен, когда в этот файл необходимо внести изменения (например, поправить конфиг на сервере).

Сеть и диагностика
curl (Client URL)
Что делает: Отправляет запросы к серверам по различным протоколам (HTTP, HTTPS, FTP). По сути, это браузер, работающий внутри командной строки.
Зачем нужна: Чтобы скачать файл из интернета, протестировать работу API, проверить, отвечает ли сайт, или отправить GET/POST-запрос на сервер.

tracert (в Linux используется аналогичная команда traceroute)
Что делает: Показывает весь маршрут, который проходят сетевые пакеты от вашего компьютера до целевого сервера (отображает каждый промежуточный узел/маршрутизатор и задержку в миллисекундах).
Зачем нужна: Для поиска проблем со связью. Если сайт не открывается, эта команда поможет понять, на каком именно этапе (у вашего провайдера, на магистральном кабеле или уже у хостинга) теряются данные.

Права доступа
chmod (Change Mode)
Что делает: Изменяет права доступа к файлу или папке для разных категорий пользователей (владелец, группа, остальные). Права задаются цифрами (например, chmod 755 script.sh) или буквами (chmod +x script.sh).
Зачем нужна: В Linux безопасность превыше всего. По умолчанию созданные файлы нельзя просто так запустить как программы. С помощью chmod вы разрешаете файлу выполняться (делать его исполняемым), закрываете важные конфиги от чужих глаз или даете права на запись.
